# go-package-quarantine

实现“会沿依赖图传播的软件包版本隔离”的 Go 服务：版本发布、直接依赖解析、
安全隔离/解除（含**风险原因叠加**、传递传播与可解释路径）、**有期限的风险豁免**、
安装解析与影响查询，并持久化图关系与审计历史。

开发环境：Go 1.23.0。

## 核心模型

- **版本身份不可变**：软件包版本由 `(名称, 版本号, 内容摘要)` 共同唯一确定。
  发布后不可更改；同一 `(name, version)` 以不同摘要再次发布会得到 `digest` 错误。
  发布时按 `(name, version)` 解析直接依赖，并把**带摘要的具体版本**存入图中。
- **发布校验**：直接依赖不存在 → `dependency` 错误；声明自环/依赖环 → `dependency` 错误；
  字段缺失、摘要格式非法、重复依赖边 → `invalid_param` 错误。失败的发布不写入任何状态。
  （在“版本不可变、依赖只指向已发布版本”的模型下，图恒为 DAG，新节点不可能经多节点
  回到自身，因此环检测主要拦截自依赖；环检测逻辑对已存在环的数据同样有效。）
- **隔离沿依赖图传播**：隔离某一具体版本后，安装解析不仅排除它本身，也排除任何
  （传递）依赖到它的版本。排除时返回 `BlockedError`，其中 `Path` 是一条
  `根版本 → … → 被直接隔离版本` 的可解释依赖路径。
- **风险按原因叠加**：隔离必须携带风险原因（如 CVE 编号）。同一版本上**不同原因的
  隔离可以并存**，各自独立解除、独立豁免；相同原因重复隔离返回 `conflict`。
  当一个版本上存在多条风险时，笼统的 `Release` 会被拒绝，必须用 `ReleaseRisk`
  显式指定要解除哪一条原因；`BlockedError` 会给出实际阻断的 `RiskReason`。
- **有期限的风险豁免（waiver）**：经批准后可临时采用某个被隔离版本，但豁免是
  **四元组精确匹配**——`(具体版本, 隔离原因, 被豁免的隔离事件序号, 有效期)`，
  因此：
  - 只放开这一条风险；同一版本后来出现**新的隔离原因**，旧豁免不覆盖，仍按新原因阻断；
  - 风险解除后又以相同原因**重新隔离**（新的隔离事件序号），旧豁免不自动覆盖，
    必须重新申请；
  - 豁免到期（`valid_until` 时刻即失效）或被撤销后立即恢复阻断；
  - 豁免只替它绑定的版本背书，不替该版本的依赖项背书（依赖上的其它风险照常传播）。
  每次成功解析都会在 `Resolution.Waivers` 中记录**实际采用了哪些豁免以及采用原因**
  （含有效期、批准人/批准单号、隔离与授予事件序号），供调用方留档。
- **安全修订快照**：每次隔离/解除/豁免授予/豁免撤销都使安全修订号（security
  revision）+1。`Snapshot()` 返回某一时刻的不可变只读视图；**一次解析全程只读取
  同一快照**，期间的发布、隔离或豁免变化只能影响下一次请求。豁免到期不产生修订
  事件，由解析在**入口按当时时钟统一判定一次**：解析进行中即使时钟越过到期点也不影响
  本次结果；而入口已到期则一定不会返回失效版本。可通过 `WithClock` 注入时钟
  （生产用真实时钟，测试用可控时钟）。
- **解除隔离的精确语义**：解除只移除目标版本上指定原因的那一条隔离，并使挂在该风险
  上的豁免随之失效（授予记录仍保留在审计历史中）。若某版本仍被其它生效隔离沿依赖
  路径影响，它不会因此恢复安装资格。
- **幂等**：发布、隔离、解除、豁免授予/撤销都要求携带外部请求号（`RequestID`）。
  - 同号 + 同内容：重放首次结果（响应中 `Replayed=true`），不重复生效、不推进修订号；
  - 同号 + 异内容：返回 `idempotent` 冲突；
  - 同一请求号不能跨操作类型复用。
  豁免的幂等载荷包含目标版本、风险原因、有效期（RFC3339Nano）、批准信息与申请备注。
- **并发保证**：所有状态变更经同一把互斥锁串行化；版本对象创建后不可变，可被
  快照无锁共享。已确认的隔离不可能被“迟到发布”绕开——新发布版本在解析时
  统一基于当前快照做污染分析（taint analysis），沿任何新边可达未豁免的隔离风险即被排除。

## API 概览

```go
svc, _ := packagequarantine.NewService("")          // "" = 纯内存；传目录则 JSONL 持久化
defer svc.Close()

// 发布（直接依赖按 name@version 解析为带摘要的具体版本）
svc.Publish(PublishRequest{
    RequestID: "req-app-1",
    Name: "app", Version: "1.0.0",
    Digest: "sha256:….", // sha256:<64 位小写十六进制>
    Deps:   []Dependency{{Name: "lib", Version: "1.0.0"}},
})

// 安全操作：风险原因精确标识每一条风险；成功即推进安全修订号
svc.Quarantine("req-q-1", Version{Name: "lib", Version: "1.0.0", Digest: "…"}, "CVE-2026-0001")
svc.Quarantine("req-q-2", Version{Name: "lib", Version: "1.0.0", Digest: "…"}, "CVE-2026-0002") // 原因叠加
svc.ReleaseRisk("req-r-1", Version{Name: "lib", Version: "1.0.0", Digest: "…"}, "CVE-2026-0001", "已修复")
// 仅当版本上恰有一条生效隔离时，才可用不指定原因的 Release

// 有期限豁免：精确关联“版本 + 风险原因”，携带有效期与批准信息
gr, err := svc.GrantWaiver(WaiverRequest{
    RequestID:  "req-w-1",
    Target:     Version{Name: "lib", Version: "1.0.0", Digest: "…"},
    RiskReason: "CVE-2026-0002",           // 必须与一条生效隔离的原因逐字匹配
    ValidFrom:  time.Now().Add(-time.Hour),
    ValidUntil: time.Now().Add(72 * time.Hour),
    Approval:   Approval{By: "security-officer", ID: "CAB-2026-042"},
    Reason:     "新版本需一周窗口完成迁移",
})
svc.RevokeWaiver("req-rv-1", gr.Waiver.Target, "CVE-2026-0002", "应急撤销")

// 一次解析全程持同一快照
snap := svc.Snapshot()
res, err := snap.Resolve("app", "1.0.0")
// err 为 *BlockedError 时：err.Path / err.RiskReason 给出阻断路径与具体风险原因
// 成功时 res.Waivers 列出本次实际采用的豁免及采用原因

// 影响查询：谁（传递）依赖了某版本、路径、各条风险及豁免状态、当前是否被排除
report, _ := snap.Impact("lib", "1.0.0")
// report.Risks[i] = {Reason, QuarantineEventSeq, Waived, WaiverGrantEventSeq, WaiverValidUntil}

// 审计历史（隔离/解除/豁免授予/豁免撤销事件，含序号、修订号与关联序号）
events := snap.AuditEvents()
```

便捷封装 `svc.Resolve(...)` / `svc.Impact(...)` 等价于“取当前快照再查询”；
需要在同一安全修订内完成多次读取时，请显式持有一个 `Snapshot`。

### 错误分类

用 `ErrorAs(err)` 取出 `*Error`，按 `Kind` 区分：

| Kind | 含义 |
| --- | --- |
| `invalid_param` | 参数错误：字段缺失、摘要格式非法、重复依赖边、豁免缺少批准人/有效期非法等 |
| `dependency` | 依赖错误：依赖不存在、自环/依赖环、解析被隔离规则阻止 |
| `digest` | 摘要错误：同 `(name,version)` 摘要不一致 / 目标摘要不匹配 |
| `idempotent` | 幂等冲突：外部请求号相同但内容不同，或跨操作复用请求号 |
| `not_found` | 目标版本不存在 |
| `conflict` | 状态冲突：重复隔离、解除未隔离的版本、多风险时未用 `ReleaseRisk`、为不存在的风险申请豁免、未到期豁免重复授予、撤销不存在的豁免等 |

解析被隔离阻止时返回 `*BlockedError`（`Unwrap()` 后 Kind 为 `dependency`），
携带 `Rev`、`Path`、`Quarantined`、`RiskReason`、`QuarantineEventSeq`。

## 持久化与审计

传入目录时，服务以三个只增 JSONL 文件持久化（每行一个 JSON 对象，写入后 fsync）：

| 文件 | 内容 |
| --- | --- |
| `graph.jsonl` | 版本节点与解析后的图关系（直接依赖，带摘要） |
| `requests.jsonl` | 外部请求号 → 已应用操作的幂等记录（含载荷哈希） |
| `audit.jsonl` | 隔离、按原因解除、豁免授予/撤销事件（全局序号、修订号、目标、原因、有效期、批准信息、关联序号） |

重启时按 `graph → requests → audit` 顺序回放即可还原全部内存状态，包括当前安全
修订号、按原因叠加的生效隔离集合与未撤销豁免（豁免到期在回放后由时钟重新派生）。

## 运行测试

```sh
go test ./...          # 功能与并发测试
go test -race ./...    # 附带竞态检测
```

测试覆盖：依赖解析与缺失依赖、自环/环检测、摘要不可变、幂等重放与冲突、
隔离的传递传播与可解释路径、**风险原因叠加与按原因解除**、
**豁免精确放开单一风险、新风险不被旧豁免覆盖、同原因重新隔离不继承旧豁免**、
**豁免有效期边界（含到期时刻）、到期取代、撤销即时失效、到期后显式撤销留痕**、
**豁免授予/撤销幂等、快照在豁免变化下的隔离性、到期与解析并发的一致性、
并发授予/撤销/解析、豁免持久化重启还原、影响查询的风险与豁免状态**，
以及安全修订快照隔离、审计历史、并发迟到发布等既有场景。
