# go-package-quarantine

实现“会沿依赖图传播的软件包版本隔离”的 Go 服务：版本发布、直接依赖解析、
安全隔离/解除（含传递传播与可解释路径）、**有期限的风险豁免**、安装解析与
影响查询，并持久化图关系、豁免与审计历史。

开发环境：Go 1.23.0。

## 核心模型

- **版本身份不可变**：软件包版本由 `(名称, 版本号, 内容摘要)` 共同唯一确定。
  发布后不可更改；同一 `(name, version)` 以不同摘要再次发布会得到 `digest` 错误。
  发布时按 `(name, version)` 解析直接依赖，并把**带摘要的具体版本**存入图中。
- **发布校验**：直接依赖不存在 → `dependency` 错误；声明自环/依赖环 → `dependency` 错误；
  字段缺失、摘要格式非法、重复依赖边 → `invalid_param` 错误。失败的发布不写入任何状态。
  （在“版本不可变、依赖只指向已发布版本”的模型下，图恒为 DAG，新节点不可能经多节点
  回到自身，因此环检测主要拦截自依赖；环检测逻辑对已存在环的数据同样有效。）
- **隔离按原因区分、沿依赖图传播**：隔离必须携带**隔离原因**（如 CVE 编号）。
  原因是隔离身份的一部分：同一版本可因不同原因被多条隔离同时命中，各自独立生效、
  独立解除/豁免。隔离某一具体版本后，安装解析不仅排除它本身，也排除任何
  （传递）依赖到它的版本。排除时返回 `BlockedError`，其中 `Path` 是一条
  `根版本 → … → 被直接隔离版本` 的可解释依赖路径，`Reason` 是终点上实际造成
  阻塞的那条（未被豁免覆盖的）隔离原因。
- **有期限的风险豁免（waiver）**：经批准后可临时使用某个被隔离版本。
  - 豁免**精确关联一条隔离**：具体版本 + 隔离原因 + 隔离事件序号，只放开这一条
    风险；同一版本后来出现的任何其它隔离原因不受影响，仍按新原因阻断解析。
    旧隔离解除后即使以相同原因字符串重新隔离，旧豁免也不覆盖（事件序号已变）。
  - 豁免带**有效期**（`ExpiresAt`，到期时刻本身即失效）与**批准信息**
    （批准人必填，可附单号/备注）；到期或撤销后立即恢复阻断。
  - 一次成功解析若采用了豁免，结果 `Resolution.Waivers` 给出每个被豁免风险的
    采用原因（版本、原因、隔离/豁免序号、从根到该版本的路径、批准人、有效期），
    同时落一条不可变的**采用留痕**（`WaiverUsageRecord`，内存模式也保留，
    持久化模式写入 `waiver_usage.jsonl`）；被阻断的解析不留痕。
- **安全修订快照**：每次隔离/解除/豁免授予/豁免撤销都使安全修订号（security
  revision）+1。`Snapshot()` 在持锁瞬间采样状态与“当前时刻”，返回不可变只读视图；
  **一次解析全程只读取同一快照**——进行中发生的隔离、豁免授予/撤销或到期判定
  都只能影响下一次请求。豁免有效性（未撤销、未到期、目标隔离仍是同一条事件）
  与状态拷贝在同一把锁、同一采样时刻下确定，不存在 TOCTOU 窗口。
- **解除隔离的精确语义**：解除只移除 `(版本, 原因)` 这一条隔离。同一版本的
  其它原因隔离、以及其它版本的隔离仍然生效。
- **幂等**：发布、隔离、解除、豁免申请、豁免撤销都要求携带外部请求号（`RequestID`）。
  - 同号 + 同内容：重放首次结果（响应中 `Replayed=true`），不重复生效、不推进修订号；
  - 同号 + 异内容：返回 `idempotent` 冲突（豁免的“同内容”包含目标、原因、到期
    时间、批准人/单号/备注；批准时间为服务端填充，不参与判定）；
  - 同一请求号不能跨操作类型复用。
- **并发保证**：所有状态变更经同一把互斥锁串行化；版本对象创建后不可变，可被
  快照无锁共享。已确认的隔离不可能被“迟到发布”绕开——新发布版本在解析时
  统一基于当前快照做污染分析（taint analysis），沿任何新边可达未豁免的被隔离
  版本即被排除；豁免撤销与解析并发时，撤销修订及之后的快照绝不会带豁免放行。

## API 概览

```go
svc, _ := packagequarantine.NewService("")          // "" = 纯内存；传目录则 JSONL 持久化
defer svc.Close()

// 发布（直接依赖按 name@version 解析为带摘要的具体版本）
svc.Publish(PublishRequest{
    RequestID: "req-app-1",
    Name: "app", Version: "1.0.0",
    Digest: "sha256:….", // sha256:<64 位小写十六进制>
    Deps:   []Dependency{{Name: "lib", Version: "1.0.0"}},
})

// 安全操作（原因是隔离身份的一部分；成功即推进安全修订号）
svc.Quarantine("req-q-1", Version{Name: "lib", Version: "1.0.0", Digest: "…"}, "CVE-2026-0001")
svc.Release("req-r-1", Version{Name: "lib", Version: "1.0.0", Digest: "…"}, "CVE-2026-0001")

// 有期限的风险豁免：精确关联“当前生效的 (版本, 原因) 那条隔离”
g, _ := svc.GrantWaiver("req-w-1",
    Version{Name: "lib", Version: "1.0.0", Digest: "…"},
    "CVE-2026-0001",
    time.Now().Add(24*time.Hour),               // 有效期（必填，须为未来时间）
    Approval{Approver: "sec-alice", Ticket: "SEC-123", Note: "补偿控制已上线"})
_ = g.Waiver.Seq                                 // 豁免的稳定标识（= 授予事件序号）
svc.RevokeWaiver("req-rv-1",
    Version{Name: "lib", Version: "1.0.0", Digest: "…"},
    "CVE-2026-0001", "批准撤回")                 // 撤销当前有效的豁免

// 一次解析全程持同一快照
snap := svc.Snapshot()
res, err := snap.Resolve("app", "1.0.0")
// err 为 *BlockedError 时：err.Path / err.Reason 给出 app → … → 被隔离版本的路径与阻塞原因
// res.Waivers 列出本次解析采用的每条豁免及采用原因（路径、批准、有效期）

// 豁免采用留痕（每次成功解析采用豁免时追加一条）
for _, rec := range svc.WaiverUsage() { /* rec.Root / rec.Rev / rec.Uses */ }

// 影响查询：谁（传递）依赖了某版本、路径、当前是否被排除、各原因隔离与豁免状态
report, _ := snap.Impact("lib", "1.0.0")
// report.Quarantines[i] = {Reason, EventSeq, Waived, WaiverSeq, WaiverExpiresAt, WaiverApprover}

// 快照时刻有效的豁免
waivers := snap.ActiveWaivers()

// 审计历史（隔离/解除/授予/撤销事件，含序号、修订号、关联事件序号）
events := snap.AuditEvents()
```

便捷封装 `svc.Resolve(...)` / `svc.Impact(...)` 等价于“取当前快照再查询”；
需要在同一安全修订内完成多次读取时，请显式持有一个 `Snapshot`。

### 错误分类

用 `ErrorAs(err)` 取出 `*Error`，按 `Kind` 区分：

| Kind | 含义 |
| --- | --- |
| `invalid_param` | 参数错误：字段缺失、摘要格式非法、隔离原因为空、豁免无批准人/到期时间已过等 |
| `dependency` | 依赖错误：依赖不存在、自环/依赖环、解析被隔离规则阻止 |
| `digest` | 摘要错误：同 `(name,version)` 摘要不一致 / 目标摘要不匹配 |
| `idempotent` | 幂等冲突：外部请求号相同但内容不同，或跨操作复用请求号 |
| `not_found` | 目标版本不存在 |
| `conflict` | 状态冲突：同原因重复隔离、解除未隔离的原因、豁免不存在的风险、风险已有有效豁免、撤销已失效豁免等 |

解析被隔离阻止时返回 `*BlockedError`（`Unwrap()` 后 Kind 为 `dependency`），
携带 `Rev`、`Path`、`Quarantined`、`Reason`。

## 持久化与审计

传入目录时，服务以五个只增 JSONL 文件持久化（每行一个 JSON 对象，写入后 fsync）：

| 文件 | 内容 |
| --- | --- |
| `graph.jsonl` | 版本节点与解析后的图关系（直接依赖，带摘要） |
| `requests.jsonl` | 外部请求号 → 已应用操作的幂等记录（含载荷哈希） |
| `audit.jsonl` | 隔离/解除/豁免授予/豁免撤销安全事件（全局序号、修订号、目标、原因、关联序号） |
| `waivers.jsonl` | 豁免快照：授予写一行，撤销再写同一豁免的更新行（回放时同序号以最后一行为准） |
| `waiver_usage.jsonl` | 每次解析采用豁免的留痕（解析根、修订号、采用的豁免与路径） |

重启时按 `graph → requests → audit → waivers → waiver_usage` 顺序回放即可还原
全部内存状态，包括当前安全修订号、生效隔离集合、豁免（含撤销/到期判定所需
字段）与采用留痕。

## 运行测试

```sh
go test ./...          # 功能与并发测试
go test -race ./...    # 附带竞态检测
```

测试覆盖：依赖解析与缺失依赖、自环/环检测、摘要不可变、幂等重放与冲突、
隔离的传递传播与可解释路径、同版本多原因风险叠加、解除不恢复其它隔离路径影响
的版本、**豁免只放开精确关联的一条风险、同版本新增原因不被旧豁免覆盖、相同
原因重新隔离后旧豁免失效、豁免到期（含到期时刻边界）、豁免撤销、豁免申请/
撤销的参数校验与幂等、豁免采用原因留痕、撤销/新风险与解析并发不得放行失效
版本、豁免与留痕的持久化重启还原**、安全修订快照隔离、审计历史、影响查询、
并发迟到发布/并发同号隔离，以及持久化重启还原。
